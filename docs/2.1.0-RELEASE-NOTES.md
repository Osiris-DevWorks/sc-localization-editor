> ⚠️ **Heads-up if Windows blocks the installer:** Smart Citizen is not yet code-signed, and Windows 11's **Smart App Control** (SAC) blocks unsigned installers, Properties → Unblock does **not** help with SAC. To install:
>
> 1. Open **Settings → Privacy & security → Windows Security → App & browser control**.
> 2. Click **Smart App Control settings** and set it to **Off**.
> 3. Run `SmartCitizen-2.1.0-Setup.exe` and finish installation.
> 4. After install, you can return to the same screen and turn Smart App Control back on if you'd like.
>
> A code-signing certificate would remove this friction permanently. Smart Citizen is a free side project, so signing will only happen if community donations cover the recurring cost, **or** if Smart Citizen reaches enough adoption to qualify for a free certificate through the [SignPath Foundation](https://signpath.org/) open-source endorsement program. Until then: SAC-off install, SAC-on after.

## Headline

Hey Smart Citizens! 2.1.0 comes at the app from both ends. If you just want the enhancements applied, there's now a **Simple mode**: one screen, one **Apply Enhancements** button, done. If you like the full workbench, everything is still there in **Advanced mode**, plus new tools for the people who live in the details, blueprint ownership tracking, route-led mission titles, and a fresh coat on the Tag Builder.

Pick your mode at install, switch anytime in the app. Simple mode uses whatever settings you last saved in Advanced, so it's a fast path, not a stripped-down one.

We also turned **Spanish** on (thank you, Thord82), added an in-app **FAQ tab** so the common questions have answers without leaving the app, and tightened up a pile of blueprint and mission bugs the testers found.

## New features

### Simple & Advanced mode (#180)

Two ways to run the same app. **Simple mode** is a single screen with one big **Apply Enhancements** button that runs the whole chain, extract, generate, apply, with a backup taken first. **Advanced mode** is the full app you already know. Choose your default during install, flip between them whenever.

### Blueprints ownership (#157, #156)

Mark the crafting blueprints you already own. Owned items get a star in a new **Owned** column, and new filters let you narrow the table to just blueprint titles or just blueprint descriptions so you can find and tag them fast. The point: see at a glance, in mission and craft listings, what you still need to hunt down.

### Mission Titles: route in the title (#166)

A new **Mission Titles** tab in the Tag Builder leads hauling, delivery, and courier titles with their route. A hauling run reads like `Area18 > Lorville - <original title>`, so you can size up a contract from the list. Configurable placement (Prepend, Append, or Replace), route arrow, separator, and how much of the location to show, all with a live preview.

### FAQ tab (#152)

The questions we hear most, answered right in the app: what files Smart Citizen touches, whether you can get banned, why Windows flags the installer, and how to undo changes. Check there first; the Discord is one click away if it's not covered.

### Spanish is live (#182)

**Español** now shows up in the language dropdown, with the interface translated by **Thord82**. Under the hood, `ui.json` moved to a human-vs-AI leaf format so we can track exactly which strings are real human translations and which are placeholders waiting on one.

### Tag Builder & enhancements polish

- **Commodity Usage element**: commodity tags can now show what an item's crafting materials feed into, on by default, with a matching **Mining Compendium** legend in the journal.
- **"None" separator** for commodity tags (#97 follow-up), so you can choose to run the flags together on purpose.
- **Stats above or below**: flip a stat block to the top of a description instead of the bottom (#153).
- **`[ACE]` / `[ACE?]` title tag** for missions that spawn an ace pilot (#158).

### ASOP ship numbering (#142)

Give a favourite ship a number in the new **#** column and it reads like `01-ShipName` in-game, so your ships sort in the exact order you want at the ASOP terminal.

### Safer edits: rotating user.ini backups (#172)

`user.ini`, every hand-entered edit you make, now gets rotating backups (up to 5, taken automatically before each change), with a **Restore user.ini** button in the Config tab. If an import or edit goes sideways, roll back to a previous snapshot; the restore itself is reversible. Smart Citizen also **warns when your data folder lives inside OneDrive**, the setup that has quietly emptied `user.ini` for some users, and offers to move it somewhere local.

## Fixes

- **Restore Backup crash** from a stale load call, fixed (#185)
- **Blueprint dropdowns**: Class / Size / Grade menus work, the "Other" type no longer lists armours, and dropdowns don't catch the scroll wheel as you pass over them (#195, #196, #197)
- **Salvage contracts** honor the Hostiles toggle and stop listing hostiles that don't match the mission (#162, #163, #165)
- **Owned column** sorts owned-first instead of by key (#189)
- **Earnable quantum drive names** get tagged correctly by mirroring `_SCItem` to the capital key (#190)
- **Meaningless typeless `[S1-A]` tag** dropped from blueprint lists (#160)
- **"Unknown" spawn bucket** no longer renders in mission details (#187)
- **Mission-header emphasis** now reads as Underline / Blue text instead of the confusing EM3 / EM4 labels (#164)
- **Switching the SC install path** to a different drive persists correctly (#150)
- **Simple mode window** opens compact and at a sensible minimum size (#180)

## Known issues

- **Handle security threat missions can still show the wrong hostiles (#186).** We reworked the handler-spawn fallback this cycle, and the hostile list changed, but a tester confirmed it's still not fully correct on the 2.1 release candidate. Rather than hold the whole release on it, we're **shipping 2.1.0 with the fix in progress and carrying #186 forward** into the next cycle. The issue stays open; if you see a mismatched hostile list on a security-threat mission, add a note there.
- **Some blueprint names don't match their changed values (#194).** A deeper inconsistency between a ship-weapon's standalone tag and its re-tag inside blueprint lists. Deferred to a dedicated fix next cycle.
- The upstream CIG data-bug workarounds documented in **Help → Known Issues** still apply (e.g. the Jorrit Dossier mislabel); those live in CIG's own data and we can only work around them.

## Under the hood

- The test suite grew to just under 1,000 (993 passing) as the new features landed with coverage, blueprint metadata, ownership tagging, ship-sort numbering, route titles, Simple/Advanced mode, OneDrive detection, and user.ini backups.
- The apply button is now labeled **Apply Enhancements** everywhere (it was "Apply to Game" / "Generate & Apply to Game"); docs, dialogs, and the guided tour all match.
