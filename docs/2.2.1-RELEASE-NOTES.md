# Smart Citizen 2.2.1

## Headline

2.2.1 is a bug-fix-only release: a handful of Critical stability and data-corruption fixes, several Blueprint Tracker matching bugs, and a round of resilience hardening against corrupt local files. No new features — those are landing in 2.3.0.

## Fixes

### Critical

- **Apply to Game crashing on a corrupt base.ini (#251).** One bad byte in an otherwise-valid base.ini — machine-local corruption, not a bug in the extracted data — crashed the whole enhancements run and, separately, could silently truncate the strings table at the bad byte. Both INI readers (`src/parser/ini_parser.py`, `scripts/generate_enhancements_ini.py`) now tolerate corrupt bytes, degrading only the affected byte instead of failing or dropping every key after it.
- **Applied global.ini missing its UTF-8 BOM, breaking every in-game string (#261).** Every prior release wrote the applied file as plain UTF-8; Star Citizen's own loc-string loader needs the BOM to reliably detect the encoding, and without it the game could fail to resolve the entire loc table — every string showing as a raw `@KeyName` placeholder instead of degrading one key at a time. Apply now writes the file exactly the way Data.p4k's own extraction does.
- **Starmap and UI text randomly corrupted by an unrelated key (#255).** `sync_key_variants()`'s variant-matching ran over the *entire* ~90k-key table, so two completely unrelated CIG loc keys could canonicalize to the same string and silently overwrite each other — most visibly, Crusader's planet name got replaced by "Stanton (Star)". An audit of a real base.ini found 14 more live collisions of this shape (comm-array button text, a mission title, ship-interior area names, Options-menu turret labels, two different thruster names merged into one). Scoped the sync to `item_Name*`/`item_Desc*` keys only, which is the boundary it was always meant to work within.

### Blueprint Tracker

- **XenoThreat limited-time-event items never showing up (#267).** The "Purgatory Camo" armor and FPS weapon sets, QuadraCell, FR-66/FR-76 shields, and NDB-26/28/30 Repeaters were only ever announced by CIG on their own website/socials — no mission ever advertises them, so mission-text scanning alone could never surface them. They now show up in Available regardless, and still resolve their real tag/class/size/grade if your own loaded strings happen to carry a matching entry.
- **Missions grouped under a reputation-tier or "MULTIPLE BLUEPRINT POOLS" header were skipped entirely.** A reputation-tiered contract's "Awarded from X level variants" sub-header (and the separate "MULTIPLE BLUEPRINT POOLS" header some mining-laser and salvage contracts use) was mistaken for a section boundary, so the scan stopped before reaching any bullets. Fixed for both header shapes.
- **Bullets carrying a "(Category)" annotation joined nothing.** CIG appends a "(Category)" suffix to some blueprint bullets — e.g. "Bendix (Fuel Nozzle)", "5CA 'Akura' (Shield)" — that the real `item_Name` entry never carries, so even a correctly-scanned bullet never matched its item. The annotation is now stripped before matching.
- **Fuel nozzles and the Mining Head family showing as garbled or duplicate untagged entries.** Some mission bullets list the de-slugified loc *key* instead of the item's real localized name (e.g. "Nozzle Fuelgiver Grin Nozzleveryfast" for an item actually named "Lindstrom"), and a few items (Helix, Hofstede, Arbor, Klein, Norfield, Harkin, RN-7s) use an informal short name with no deterministic relationship to their key at all. Both are now resolved — generically via a key-slug reversal for the deterministic case, and via a small alias table for the rest — so all 8 known fuel nozzle variants and the whole Mining Head family join their real item instead of appearing as separate untagged entries.
- **Refueling missions showing garbled nozzle names in the actual in-game mission text, not just the Blueprint Tracker.** A separate, deeper bug: fuel nozzle blueprint rewards don't link back to a resolvable entity name in CIG's own data the way other craftables do, so the enhancement *generator* itself was falling back to writing a de-slugified filename into the applied global.ini — visible directly on the game's Contracts screen, independent of anything the Blueprint Tracker does. Fixed at generation time for all 8 known variants; re-run Generate Enhancements and Apply to Game to pick it up on missions you've already seen.

### Other fixes

- **Mission Titles page: 7 checkboxes never armed Save Tag Changes (#259).** Toggling "Standardize hauling mission names," any of the shorten/underline checkboxes, or Cargo/Haul/Rank abbreviations updated the live preview but never lit up the Save button — so the change silently didn't persist unless you happened to touch an unrelated setting first.
- **Generate Enhancements staying stuck disabled after a channel switch (#273).** Switching LIVE/PTU/HOTFIX/TECH-PREVIEW left the button reflecting whichever state the *previous* channel ended in; a channel that genuinely needed (re)generation could show the button disabled with clicks doing nothing. Extended the same fix to Save Tag Changes and Apply Owned Tags, which had the identical problem — neither channel-appropriate correctness (empty or not) is recorded per channel, so both now light up on every switch, favoring "let me apply" over a false "nothing to do."
- **Auto-detect Star Citizen install path across all local drives (#269).** A fresh profile only checked the default drive; installs on any other drive letter required manually browsing every time. The Config tab now finds it automatically regardless of drive.
- **Crash: entering a custom value on an Import INI conflict raised `TypeError: tr() got multiple values for argument 'key'`.** The custom-value prompt passes the loc key being displayed as an interpolation variable named `key` — natural to write, but collided with `tr()`'s own first parameter of the same name. Renamed the parameter so `key` is free for any caller to use.

### Resilience hardening

Following on from #251, every other place the app reads its own local state files now tolerates corrupt bytes the same way, instead of crashing or silently discarding data: the DataForge diff manifest, DataForge patch files, `settings.json` (portable mode), and the user.ini backup-comparison path (which also now compares bytes rather than decoded text, fixing a related issue where an identical re-save could still churn a real backup out of the 5-slot rotation).
